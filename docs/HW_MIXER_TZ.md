# ТЗ: универсальный аппаратный wavetable-микшер

Статус: проект, не релиз. Репозиторий `musicplayer2`, отдельно от релизного
`karabas-go-core-player` (`v1.0b`).

## 1. Цель

Снять с VexRiscv основную нагрузку микширования сэмпловых трекерных голосов и
сделать один общий FPGA-микшер для **MOD, XM, IT и S3M**.

Микшер не должен знать формат модуля. Форматные движки на CPU считают тик,
эффекты, огибающие, NNA и аллокацию голосов; FPGA получает параметры голосов и
выдаёт готовый stereo PCM в существующий audio FIFO.

В первый этап **не входит**:

- AY/PT3/PT2/STC — это не wavetable, их не трогаем;
- MP3/WAV — это готовый PCM, микшер не нужен;
- полный IT-синтезатор с резонансными фильтрами и stereo samples — только после
  стабильного базового микшера;
- замена CPU-плеера целиком. VexRiscv остаётся управляющим контроллером.

Ограничения:

- без внешних декодеров и синтезаторов;
- сохранить F12, паузу, громкость и MikMod fallback;
- качество важнее максимального числа голосов;
- релиз только после проверки на всех целевых платах;
- не выкладывать внутренние заметки/ТЗ в релизный репозиторий.

## 2. Текущая база и ресурсы

Плата: Spartan-6 (XC6SLX25-класс), 24 051 логическая ячейка, 38 DSP48A1,
52 BRAM, 3 758 слайсов, 75 МГц.

По текущим отчётам PAR:

| Ресурс | Занято | Свободно |
|---|---:|---:|
| DSP48A1 | 21/38 | 17 |
| RAMB16 | 37/52 | 15 |
| Slices, Go | 3 138/3 758 | ~620 |
| Slices, Mini G | 3 508/3 758 | ~250 |
| Slices, Mini | ~3 532/3 758 | ~225 |

Вывод: DSP и BRAM есть, но **слайсы на Mini G/Mini почти закончились**.
Поэтому проектировать параметризуемый микшер:

- Go: цель 64 голоса;
- Mini G: сначала 32 голоса, при успешном fit можно пробовать больше;
- Mini: 32 голоса или меньше;
- если ресурсов не хватает — fallback на текущий программный путь.

## 3. Поддержка форматов

| Формат | Текущий движок | Решение |
|---|---|---|
| MOD | `src/sw/mod_fpga.c`, `fastmix` | подключить к HW-микшеру |
| XM | `src/sw/xm_fpga.c`, `fastmix` | подключить к HW-микшеру |
| IT | `src/sw/it_fpga.c`, новый движок + `fastmix` | подключить, NNA/эффекты на CPU |
| S3M | `src/sw/mikmod_fpga.c`, `VC_WriteBytes` | отдельный адаптер или нативный S3M |
| S3M + AdLib/OPL | MikMod | fallback на MikMod, HW sample-микшер не подходит |
| PT3/PT2/STC | `src/sw/ay_fpga.c` | не трогать |
| MP3/WAV | `src/sw/mp3_fpga.c` и др. | не трогать |

Требование: у каждого движка должен быть признак `supports_hw_mix`.
Если формат не поддержан, голосов больше лимита, есть AdLib или ошибка —
использовать старый путь.

## 4. Архитектура микшера

### 4.1. TDM-движок

- Выход 48 кГц stereo, 16 бит.
- 75 МГц / 48 кГц = 1562.5 такта на sample; использовать sample-enable
  1562/1563 (дробный аккумулятор).
- До 64 голосов, 20–24 такта на голос.
- 64 × 24 = 1536 тактов; остаток — output/saturation/служебные операции.
- Один конвейерный движок, а не 64 независимых канала в логике.

Стадии конвейера:

1. выбор голоса и чтение состояния из BRAM;
2. чтение двух сэмплов из line cache;
3. линейная интерполяция;
4. умножение на gain L/R;
5. накопление;
6. обновление pos/frac/dir;
7. output saturation.

### 4.2. DSP48A1

- 3–5 DSP: интерполяция + L/R gain, при необходимости фильтр.
- 18-битные входы DSP достаточны для 16-битного сэмпла и 16-битного
  коэффициента.
- Позицию и фазу хранить в 32-битной логике, не в DSP.
- Аккумулятор 32/40 бит; saturation на выходе.
- Никакого float в микшере.

### 4.3. Состояние голосов в BRAM

На голос:

- `sample_base`;
- `length`;
- `loop_start`, `loop_end`;
- `loop_mode`, `pingpong`;
- `sus_loop_start`, `sus_loop_end`;
- `pos`, `frac`;
- `step`;
- `gain_l`, `gain_r`;
- `ramp_target`, `ramp_current`;
- `flags`: active/master/bg/8-16 bit.

Требования:

- 64 голоса × 8–12 32-битных слов;
- два банка: shadow для CPU и active для микшера;
- CPU пишет только изменившиеся голоса в shadow, затем commit;
- микшер переключает банк на границе тика/сэмпла;
- pos/frac/dir принадлежат микшеру, CPU читает их только для trace/UI;
- ожидаемо 2–4 BRAM на состояние, не один.

## 5. Сэмплы, line cache и SDRAM

Это главный риск, важнее DSP.

- Прямое чтение из SDRAM на каждый голос/кадр не делать.
- Нужен line cache: 16–32 сэмпла на голос.
- 64 голоса × 32 × 2 байта ≈ 4 КБ; с тегами и double-buffer — 4–8 BRAM.
- Предвыборка следующей линии при приближении к концу текущей.
- Арбитр SDRAM:
  - аудио-запросы выше CPU;
  - burst-чтение линии;
  - loop/pingpong/sample end учитывать при заполнении;
  - CPU cache не должен засоряться потоковыми сэмплами.
- Ориентир по полосе: 64 × 48k × 2 чтения × 2 байта ≈ 12.3 МБ/с.
  По полосе нормально; по latency и переключению строк нужен кэш.
- Поддержать 8- и 16-битные сэмплы, loop/pingpong и sample end.
- Stereo samples — только после базового микшера.

## 6. Интерфейс CPU ↔ FPGA

Добавить memory-mapped блок в `src/rtl/soc/menu_soc.v`.

Минимальные регистры:

- `voice_count`;
- `commit`;
- `active_bank`;
- `status` (busy, underrun, overflow);
- глобальная громкость;
- пауза/стоп;
- базовый адрес таблицы голосов.

Обновление:

- CPU раз в тик пишет только изменившиеся голоса;
- commit в конце;
- аппарат читает новый банк;
- CPU читает позиции/статус для UI и trace.

Оценка нагрузки: 64 × ~32 байта × 50 Гц ≈ 100 КБ/с — не проблема.

## 7. Выход и интеграция

- Микшер пишет stereo PCM в существующий audio FIFO
  (`src/sw/audio.c`, `src/rtl/soc/menu_soc.v`).
- Громкость/пауза — регистры.
- Нужно решить:
  - аппаратный low-pass вместо `mixer_write()` или постобработка на CPU;
  - что делать со спектром: `analysis_push()` сейчас вызывается в
    `src/sw/mixer.c`. Для HW-микшера либо отдельный tap/BRAM, либо отключать
    спектр для HW-форматов.
- `MIX/U` должны продолжать работать.
- F12 должен сбрасывать CPU и состояние микшера.
- `mixer_write()`/`audio_write()` не должны дублировать запись PCM.

## 8. FPU

FPU для IT и аппаратного микшера не нужен: все активные пути integer/fixed-point.
Но удаление FPU делать отдельным этапом.

Порядок:

1. Пересобрать CPU без F-расширения: `rv32im`, ABI `ilp32`.
2. Пересобрать прошивку с `-march=rv32im -mabi=ilp32`.
3. Проверить `objdump` на отсутствие `fmul.s`, `fadd.s`, `flw`, `fsw` и т.п.
4. Убрать/заглушить неиспользуемые float-пути MikMod
   (`Mix32ToFP_Normal/Stereo`, `DMODE_FLOAT`).
5. Проверить FatFs `ftoa`/double-пути; если не используются — исключить.
6. Синтезировать и сравнить LUT/slices/registers/DSP/BRAM/timing с `rv32imf`.

Ожидание: FPU освободит часть слайсов, но **не гарантирует fit 64 голосов на
Mini G**. Не удалять FPU вслепую; это отдельная проверяемая задача.

## 9. S3M: два варианта

### A. MikMod export

- тикать MikMod, но не микшировать через `VC_WriteBytes`;
- вытаскивать `VINFO`/`VNF` (sample, pos, step, volume, pan) в общий
  `hw_voice_t`;
- плюс: проверенный S3M-плеер;
- минус: вмешательство в `mikmod/playercode/virtch2.c`/`virtch.c`, риск.

### B. Нативный S3M

- по образцу нового IT-движка;
- плюс: единый интерфейс;
- минус: много работы: эффекты, OPL/AdLib, совместимость.

Для S3M с AdLib-инструментами аппаратный sample-микшер не использовать —
fallback на MikMod.

## 11. Критерии приёмки

- 64 голоса на Go или 32 на Mini G/Mini без underrun.
- `MIX` стабилен, `U` не растёт.
- CPU load заметно ниже; debug `%`/`r%` подтверждает.
- Выход совпадает с `fastmix` в заданном tolerance.
- Loop/pingpong/sustain/ramp/sample end без щелчков.
- Atomic update: нет полуобновлённых параметров.
- Fit и timing на каждой плате.
- Не ломаются MOD/XM/IT/S3M, F12, пауза, громкость, MikMod fallback.
- FPU removal не ломает ни один формат.
- Релиз только после проверки на железе.

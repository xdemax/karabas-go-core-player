# ТЗ: компактный быстрый микшер трекерных голосов

Это задание для отдельного исполнителя (Claude/другого coding agent). Нужен не новый
трекерный плеер и не «частичный реплеер», а **только PCM-микшер**: готовый replayer
(сначала libxmp, потом при желании MikMod) отдаёт состояние голосов, микшер выдаёт
interleaved stereo 16-bit PCM 48 кГц.

## 1. Зачем

На Karabas Go стоит VexRiscv `rv32im` на 75 МГц, без FPU, с I/D-кэшами по 4 КБ.
MikMod тянет 48 кГц, но качество IT/S3M ограничено. libxmp по качеству лучше, но его
штатный микшер не успевает: на 4-канальном `Keijsig.it` `MIX` падает до 20–30 тысяч
сэмплов/с вместо 48 000.

Нужно заменить **только внутренний цикл сведения голосов** на компактный fixed-point
микшер, сохранив libxmp-реплеер эффектов. Цель — вернуть 48 кГц и качество при
разумной загрузке CPU.

## 2. Железо и текущая система

- FPGA: Xilinx Spartan-6 `xc6slx25`, 75 МГц.
- CPU: VexRiscv, `rv32im`, без FPU, I$ 4 КБ, D$ 4 КБ, SRAM общая с видео.
- Память: 3 МБ SRAM под код/кучу/стек; 32 МБ SDRAM, окно `0x10000000`.
- Аудио: стерео FIFO 8192 сэмпла, 48 кГц, регистр свободного места `0x74`.
- Текущий общий выход: `src/sw/mixer.c`: 12 кГц low-pass + анализатор + запись в FIFO.
- Текущая сборка: `26112345` (MikMod normal, MOD/XM native).
- libxmp лежит в `src/sw/libxmp`, но в сборку не входит. Его можно взять как источник
  тестов и как целевой replayer.

## 3. Границы задачи

Входит:

- новый переносимый C-модуль микшера (например, `src/sw/fastmix.c/.h`);
- fixed-point сведение 8/16-bit mono сэмплов;
- linear interpolation (обязательно), опционально 4-point cubic;
- forward и ping-pong loops;
- volume/pan/ramp без щелчков;
- суммирование до 64 голосов, с ограничением/пропуском тихих голосов при перегрузе;
- блоковый API: свести N кадров за вызов;
- host-тесты и target-бенчмарк;
- патч интеграции в libxmp (`src/sw/libxmp/src/mixer.c` или отдельный backend).

Не входит:

- загрузка модулей, парсинг эффектов, envelopes, NNA, IT-фильтры;
- замена libxmp-плеера;
- MP3/OGG;
- UI, файловый браузер, SD-драйвер;
- ESP32 и внешние декодеры.

## 4. Формат голоса

Предлагаемый публичный API (можно менять имена, но не смысл):

```c
#define FM_MAX_VOICES 64

enum {
  FM_8BIT       = 1u << 0,
  FM_LOOP       = 1u << 1,
  FM_PINGPONG   = 1u << 2,
  FM_ACTIVE     = 1u << 3
};

typedef struct {
  const void *data;       // signed 8-bit or signed 16-bit, mono
  uint32_t length;        // frames
  uint32_t loop_start;    // frames
  uint32_t loop_end;      // frames, exclusive

  uint32_t pos;           // 16.16 fixed point
  uint32_t step;          // 16.16 samples per output frame
  int32_t  volume;        // 0..256 (Q8), 256 = unity
  int32_t  pan;           // -128..127
  uint16_t ramp;          // frames left for a volume/pan ramp
  uint16_t ramp_len;      // total ramp length
  uint8_t  flags;
  uint8_t  reserved[3];
} fm_voice_t;

void fm_reset(void);
void fm_mix(int16_t *dst, int frames, const fm_voice_t *voices, int nvoices);
```

Требования к полям:

- `pos` и `step` — 16.16. Для 48 кГц и сэмплов 8–48 кГц этого достаточно.
- `step` может быть больше 1.0 (downsampling) и меньше 0.01 (высокие ноты).
- `loop_end` исключающий; при `FM_PINGPONG` направление хранится/выводится внутри
  голоса, либо добавляется явное поле `dir`.
- `volume` Q8; `pan` линейный или equal-power — зафиксировать в коде и тестах.
- Ramp от старого значения к новому за `ramp_len` кадров. Без ramp при смене
  ноты/громкости слышны щелчки.

## 5. Алгоритм и производительность

Обязательно:

- только целочисленная арифметика: `int32_t`, при необходимости `int64_t` только
  вне inner loop;
- никаких `float`, `double`, `malloc`, `printf`, `memcpy` в audio-path;
- **channel-major** обход: для каждого голоса цикл по блоку, локальные `pos/step/gain`
  в регистрах, затем сложение в общий `int32` буфер;
- границы loop/end обрабатывать **вне** inner loop; не делать `%` и ветвление на
  каждый сэмпл;
- linear interpolation:
  `s = s0 + ((s1 - s0) * frac) >> 16`;
- не использовать указатель на функцию на каждый сэмпл; выбор 8/16-bit и linear
  делать один раз на блок/голос;
- для 4–16 голосов не сканировать 64 неактивных голоса на каждый сэмпл;
- при >32 активных голосах разрешено отбрасывать самые тихие (как сейчас в XM),
  но не оставлять дыр в нумерации/состоянии;
- на выходе saturate в `int16_t`; внутренняя сумма — `int32_t`;
- не менять `mixer_write()`/общий low-pass/анализатор без отдельного решения.

Ориентиры по CPU (только микшер, без UI, 75 МГц):

- 4 голоса, 48 кГц, linear, 16-bit: **< 10 млн циклов/с**;
- 16 голосов: **< 30 млн циклов/с**;
- 32 голоса: не более ~55 млн циклов/с, с отбрасыванием тихих;
- полный плеер на `Keijsig.it` (4 канала): `MIX ≈ 48 000`, `U` не растёт;
- код микшера < 24 КБ, горячий цикл желательно < 2–3 КБ.

## 6. Тесты и приёмка

Host-тесты (Linux, без FPGA):

1. 1 кГц синус 8-bit и 16-bit: частота и амплитуда с допуском;
2. linear interpolation: сравнение с эталонным float-микшером на host (эталон только
   в тесте, не в прошивке);
3. loop forward: бесшовный переход, позиция не уходит за `loop_end`;
4. ping-pong loop: корректный разворот, без чтения за границами;
5. volume/pan ramp: нет шага больше заданного, нет клика;
6. 64 голоса: нет переполнения `int32`, saturate корректный;
7. длина блока 1, 255, 256, 512 кадров;
8. сравнение с текущим libxmp на тестовых модулях: `Keijsig.it`, `GRD_TanDan.it`,
   обычный MOD/XM; оценка спектра/частот, отсутствие дропаутов.

Target-тесты:

- замер `R_CYCLES` вокруг `fm_mix()` на 4/8/16/32 голосах;
- отчёт: cycles/block, cycles/output sample, оценка % CPU при 75 МГц;
- полный трек: `MIX` из UI, `U` (underruns), прослушивание.

Критерий готовности:

- `Keijsig.it` играет без подёргиваний и без «плавающего» тона;
- 4 голоса укладываются в бюджет;
- при 16 голосах нет underrun;
- A/B с текущей сборкой `26112345` не хуже по качеству;
- изменения не ломают MOD/XM/S3M/IT и не требуют FPU.

## 7. Интеграция с libxmp

Нужен адаптер, который:

1. оставляет без изменений загрузчики, эффекты, envelopes, NNA и порядок тиков;
2. на каждом тике/блоке заполняет `fm_voice_t` из внутренних `mixer_voice` libxmp;
3. вызывает `fm_mix()`;
4. отдаёт PCM в `mixer_write()` или в общий буфер.

Если libxmp-микшер нельзя заменить точечно, допускается отдельный backend в
`src/sw/libxmp/src/mixer.c`, но **без переписывания replayer**.
